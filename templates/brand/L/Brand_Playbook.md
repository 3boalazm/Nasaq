# {{name}} — brand playbook (size L)

The production standard. Read section 0 once, then only the section for the phase in hand. An output is done when its acceptance check passes and the evidence is recorded. Numbers marked *default* are starting points: confirm or change them in the phase spec.

## 0 Operating rules

### 0.1 Feedback

1. Rounds per phase: 2 (*default*; the agreed number is in Brand_Roadmap.md section 2). A further round is a change request.
2. One consolidated list per round, sent by the client decision owner. Comments that contradict each other go back to that person to settle.
3. Every comment is logged in Handoff.md (Feedback log) with one outcome: accepted, declined with the reason, or change request.
4. Reply window: 3 working days (*default*). A late reply moves the dates by the same number of days, recorded in Decisions.

### 0.2 Change requests

A change request is any of: a new deliverable or application, a new language or market, reopening an approved gate, or a round beyond the agreed number.

1. Log it in Handoff.md (Change requests) before any work on it.
2. State the effect on dates, effort, cost and items.
3. The approver accepts or declines in writing.
4. If the size changes, run the rescope in Nasaq and keep the RESCOPE_NOTE.md it produces.

### 0.3 AI use

1. AI output is a draft. A named person reviews it before it reaches the client or a master file.
2. Every AI-made image or text kept in the project is logged in Handoff.md (AI log): tool, version, date, purpose, reviewer.
3. No confidential client material goes into a tool the client has not approved.
4. Final marks are drawn as vectors by the designer. An AI image is never master artwork: ownership and registration of AI-made marks are uncertain, and counsel confirms.
5. AI imagery in a deliverable: the tool's licence terms go in the Asset register, and the client is told where it is used.
6. A research claim from an AI tool is UNVERIFIED until checked against a dated source.
7. An AI agent never approves a gate.

## 1 Discovery: research framework

| Question | Method | Minimum evidence | Output |
|---|---|---|---|
| What business problem must the identity solve? | Questionnaire, stakeholder interviews | The owner's statement and 2–3 measures of success | Problem statement |
| Who is the audience? | Client data, customer interviews (5 per main segment, *default*) | Segments with needs, each with a source | Audience segments |
| How big is the market and where is it going? | Desk research | Dated sources; estimates tagged ASSUMPTION | Market note |
| Who competes? | Visual and verbal audit of 5 direct and 3 indirect competitors (*default*) | Screens or photos, dated | Competitor audit and a map of the open space |
| Strengths, weaknesses, opportunities, threats | Workshop | Each point tied to a finding | SWOT |
| How is the brand seen now? | Reviews, social, sales team, short survey | Quotes or counts, with source | Perception summary |
| Can the name and mark be used? | Register search in each target market | Search date and result (screening only; counsel confirms) | Screening record |

Acceptance for the research brief:

- Every finding carries a source, a date and an evidence tag.
- At least 5 insights, numbered INS-1…, each with one stated consequence for the design.
- The client approves the brief at the gate. Later decisions cite insight ids.

## 2 Strategy: required outputs

| Output | Must contain | Accepted when |
|---|---|---|
| Purpose | Why the brand exists, in one sentence | Stakeholders agree it is true of the business today |
| Vision and mission | Where it is going; what it does, for whom | Each fits in one sentence |
| Positioning | Audience, category, difference, reason to believe | It names a difference the competitor audit shows nobody owns |
| Personas | 2–4, built from the audience segments | Each cites Discovery evidence, not invention |
| Value proposition | Benefit per persona, with proof | Every benefit has a proof point |
| Personality | 3–5 traits, each with "is / is not" | A designer can accept or reject a visual with it |
| Messaging framework | Core message, 3 pillars, proof per pillar, in AR and EN | Arabic is written in Arabic, not translated word for word |
| Tone of voice | 3–4 principles, each with a do and a don't example, AR and EN | A non-writer can rewrite a sample paragraph with it |
| Architecture | Master brand, sub-brands, products, naming rule | Every current and planned offer has a place |
| Differentiation | 3 points against named competitors | Each is backed by evidence |
| Archetype (optional) | One archetype and why | Used only if it helps the team decide |

## 3 Identity core: production spec

### 3.1 Routes

Each route has a one-sentence idea, cites the positioning, two personality traits and the insight ids it answers, and is shown first in black, in AR and EN, on the same three applications as the other routes.

### 3.2 Choosing a route

Score each route 1–5 on: strategic fit, difference from the competitor audit, AR/EN parity, legibility when small, reproduction in one colour, stretch across the applications in scope. The scores inform; the decision owners decide, and the reason goes in Decisions.

### 3.3 Components

| Component | Spec to write | Accepted when |
|---|---|---|
| Logo set | Primary, secondary lockup, symbol, wordmark; AR, EN and bilingual | Every version exists as a vector and passes AT-BASE-LOG |
| Colour versions | Full colour, one colour, reversed, black, white | Each is legible on its intended ground |
| Clear space | Defined in units of a part of the mark | Shown on every lockup |
| Minimum size | Per version, in mm for print and px for screen; a 16 px favicon version | Read on a proof at that size |
| Responsive logo | 3–4 steps from full lockup to symbol, with the width where each applies | Tested at each width |
| Misuse | 6–10 don'ts | Each shown as an example |
| Type | AR and EN families, roles, scale, fallback fonts, numerals policy | Licence covers every use in scope; native-reader check passed |
| Colour | Primary, secondary, neutral and functional; HEX, RGB, CMYK, and Pantone when spot printing is in scope; proportions | Contrast table done; one physical proof matched |
| Graphic elements | How they are built and where they go | A second designer rebuilds one from the rule |
| Iconography | Grid, stroke, corners, starter set | New icons match without the author |
| Illustration | Style rule and when it is used | Two samples by different hands match |
| Photography | Subject, light, framing, treatment; sourcing and licence | A mood set of 10 images approved |

## 4 System

- Guide contents: strategy summary, every component in 3.3, layout grid, application rules, misuse, file index.
- One source of truth for tokens (colour, type, spacing). The guide and the files read from it.
- Sub-brand rules follow the architecture in section 2.
- Stretch test: the system applied to the smallest, the largest and the most text-heavy application in scope.
- The guide is delivered as a PDF and as an editable version the client can update.

## 6 Handover: delivery spec

### 6.1 Formats

| Asset | Deliver |
|---|---|
| Logos | SVG, PDF and EPS (vector); PNG with transparent ground at 3 sizes; every version in 3.3 |
| Colour | Values file with HEX, RGB and CMYK (and Pantone if used); swatch file for the design tool |
| Source files | Editable originals, text live, linked assets packaged |
| Fonts | Licence proof and download source. Font files only when the licence allows passing them on |
| Templates | Editable files in the tool the client's team uses, tested by AT-BASE-TPL-01 |
| Guide | PDF and an editable version |

### 6.3 Names and versions

- Name: `brand_asset_variant_lang_colour_mode_v1.0.ext`, for example `acme_logo_primary_ar_fullcolour_rgb_v1.0.svg`. Lower case, no spaces.
- v0.x is a draft. v1.0 is the approved version. A change after delivery raises the number; the old file moves to 99_Archive and is not deleted.

### 6.4 Rights and licences

Write down, following the contract (this is not legal advice): what the client owns and from when; what is licensed and not owned (fonts, stock, AI imagery) and in whose name; whether unused routes stay with the studio; whether the studio may show the work.

### 6.5 After delivery

Name the person who owns the guide on the client side, the date of the first review, and how changes are requested.
